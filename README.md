A browser-first design editor with a reusable Rust document engine compiled to WebAssembly. The editor now follows the structure and interaction conventions of the current Figma Design UI, while retaining the PixlPrfct name. It supports local drafts and self-hosted account and team workspaces. The current editor also supports optional simultaneous editing and explicit conflict recovery for team documents; those workflows require a compatible self-hosted server.

The app opens at **All projects** (`/`). Create a design, import a `.pixl` project, or open an existing project from its card. Search, sorting, and grid/list views help find saved work. Each project opens in a separate editor route; **All projects** in the editor saves changes and returns home. Local projects stay in this browser, while the Cloud projects collection uses your signed-in account.

**New design → SVG Animation** opens a separate SVG animator with SVG import,
property keyframes, path morphing, motion paths, custom Bézier easing, a docked timeline,
playback, click/hover triggers, and animated SVG export with a live preview.
Editable timelines save as `.pixl` projects. See the [SVG animator walkthrough](https://ninefingerwoodshop-ops.github.io/pixlprfct/#svg-animator)
and [SVG Animation guide](docs/SVG_ANIMATION.md) for the workflow, verification, and current limitations. It is included in the Windows v0.1.1-alpha.18 preview. Select, move, copy/paste, or delete multiple timeline keys together; apply easing to a selection, or set its exact start and proportional duration. Copy transform and appearance keys onto another element, or reverse a selection with its easing. Duplicate keys at the playhead with Cmd/Ctrl+D, or Shift-drag to align with the playhead and other keys. Each group edit is one undo step.

The next source update adds previous/next-keyframe navigation with Alt/Option+Left/Right or the timeline menu, preserving your selection and revealing the playhead when zoomed. This is not yet included in the Windows alpha.18 download.

The contextual inspector includes 18 blend modes, persistent aspect-ratio locking, text resizing and horizontal/vertical alignment buttons, arrow endpoint swapping, and selection-specific vector/image actions. These properties participate in Rust validation, undo, saved documents, and component overrides. Blend modes render in Canvas, SVG, and HTML/CSS; Plus darker is not yet supported. The selection-by-selection reference survey and remaining gaps are tracked in `inspector-parity.json`.

Selecting a rectangle also exposes 90° rotation, horizontal/vertical flips, and Edit object (conversion to an editable closed Bézier path). Orthogonal transforms preserve asymmetric corner radii and remap gradients. Fill and stroke swatches open nonmodal paint popovers with saturation/brightness and hue controls, hex, opacity, page colors, linear/radial gradients, and local color-variable binding. Free-angle rotation, masks, Boolean operations, paint stacks, and corner smoothing are still pending.

## Run locally

Requires Rust with the `wasm32-unknown-unknown` target, a native C/C++ linker for Rust tests, and Node.js 24 or newer (the API tests use node:sqlite).

```sh
rustup target add wasm32-unknown-unknown
npm ci
npm run build
npm test
npm run dev
```

Open http://127.0.0.1:5173. The supported Sites runtime serves the editor at `/editor/index.html` and the cloud API at `/api/documents`. After the first build, apply `drizzle/0000_flaky_phalanx.sql` locally with `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_flaky_phalanx.sql` once. Local preview sign-in uses the starter’s development-only account; hosted sign-in is platform-owned. After changing editor assets, run `node scripts/prepare-editor.mjs`. For the standalone local-only editor, use `npm run build:editor` and `npm run dev:editor` on port 4173; this overwrites the deployment output, so run the full build again before publishing. The build uses wasm-pack's native ES-module `web` target (https://wasm-bindgen.github.io/wasm-pack/book/commands/build.html).

## First milestone

- Canvas pan/zoom, rectangles, ellipses, text, and visual frame backgrounds.
- Shape and pen menus with line, arrow, polygon, star, point-by-point pen, and freehand pencil tools. Drag to draw shapes; Shift constrains proportions or line angles, and Alt draws from the center. Vector color and stroke weight are editable, with normalized geometry that survives resizing, history, save/load, and PNG/JPEG/SVG export.
- Multiple pages: create, rename, switch, and delete with undo. Each page has independent layers and an in-session pan/zoom position.
- Multi-selection, marquee selection, dragging, single-object corner resizing, arrow-key nudging, and axis-constrained movement while holding Shift.
- Align to selection bounds, distribute equal gaps, and batch fill, duplicate, delete, and move operations with one undo step per operation.
- Vertical navigation rail, resizable file sidebar, searchable layer list, compact properties inspector, and floating drawing toolbar.
- Layers, visibility, fill, position, dimensions, duplicate/delete, and layer order.
- Drag Components rows directly to sort the library; the blue line indicates before/after placement. Alt+Up/Down on a component row also reorders. Library order is saved in the document and supports undo/redo independently of canvas stacking.
- Rust-backed hit testing, document validation, and 100-step undo/redo.
- Browser-local autosave, `.pixl` JSON save/load, and SVG export.
- Text controls for font family, size, weight, alignment, line spacing, wrapping, and fitting the box height to its content. Double-click canvas text to focus the content editor.
- An editable starter composition to explore immediately.

Shortcuts: V select, H pan, F frame, R rectangle, O ellipse, T text, Shift+1 fit page, Shift+2 fit selection, Space+drag pan, Ctrl/Cmd+Z undo, Ctrl/Cmd+Shift+Z redo, Ctrl/Cmd+D duplicate, Ctrl/Cmd+S save, Ctrl/Cmd+A select all visible objects on the page. Scroll pans; Ctrl/Cmd+scroll zooms. Shift-click toggles canvas objects, Shift-click selects a layer range in the sidebar, and Ctrl/Cmd-click toggles individual sidebar layers. Alt+A/D/W/S aligns the selection left/right/top/bottom. Click to place a shape, then resize it. Text content is edited in the inspector. The menu and Help rail button show shortcuts.

Drawing shortcuts: L line, Shift+L arrow, P pen, Shift+P pencil. Click pen anchors for corners or drag to create mirrored Bézier handles, then press Enter to finish an open path or click the first anchor to close it. Double-click a vector, press Enter with it selected, or use **Edit vector points** to drag its anchors and handles. Alt-drag an anchor to add handles; Enter exits editing. Escape cancels an unfinished drawing. Polygon and star are in the Shape tools menu. Clicking without dragging places a default-size shape.

Press K for Scale: drag from the lower-right of a selection or apply a percentage in the inspector. Scaling keeps the upper-left fixed and changes text sizes and vector stroke weights along with the geometry. Multi-layer scaling commits as one undo step. Values beyond document limits are rejected atomically. Scale follows the [Figma scale tool's proportional resizing behavior](https://help.figma.com/hc/en-us/articles/360040451453-Scale-layers-while-maintaining-proportions); alternate scale anchors are not implemented.

Group one or more layers with **Ctrl/Cmd+G** and ungroup with **Ctrl/Cmd+Shift+G** (or **Ctrl/Cmd+Backspace**). Groups are real container layers and can nest without flattening existing groups. A canvas click selects the outer group; double-click or **Enter** moves one nesting level inward, **Shift+Enter** selects the parent, and **Ctrl/Cmd-click** selects the deepest hit. **Tab / Shift+Tab** on the canvas selects the next / previous sibling. Select individual children directly in Layers.

Group bounds automatically follow their visible children; an all-hidden group has zero-size bounds. Moving a group moves its entire subtree. Resizing a group changes child positions and dimensions without scaling text size, strokes, or effects. Nested frames retain their own child constraints, and constraints pass through groups when an enclosing frame resizes; **K Scale** scales those properties too. Groups can align and distribute alongside other layers. Expand/collapse and rename them in Layers, and drag one or several selected layers into or out of a group. Ungrouping promotes only the selected container's immediate children, preserves nested groups and stacking, and is one undo step. Removing the last child removes the empty group. Groups preserve their hierarchy through copy/paste, duplication, saved documents, component instances, and export, and participate as single auto-layout children. **Shift+A** converts a selected group to an auto-layout frame without adding a wrapper.

These interactions follow [Figma's groups and frames behavior](https://help.figma.com/hc/en-us/articles/360039832054-The-difference-between-frames-and-groups), [nested layer selection](https://help.figma.com/hc/en-us/articles/360040449873-Select-layers-and-objects), and [group resizing](https://www.figma.com/best-practices/groups-versus-frames/).

Remaining replacement work is tracked in `roadmap.json`; a feature deployment does not mean full Figma parity.

Ctrl/Cmd+C, X, and V copy, cut, and paste selected layers, including frame descendants, group relationships, embedded images, typography, appearance, constraints, and auto layout. The clipboard uses a versioned PixlPrfct JSON payload, so copies work across pages and PixlPrfct files/tabs with independent layer IDs. Selecting a frame or group makes it the paste destination; otherwise repeated pastes offset on the page. The file menu's **Paste over selection** places copied roots at the selected layer's position as siblings. Ctrl/Cmd+Shift+V also requests this when the host delivers the shortcut; some embedded browsers intercept it, so use the menu there. Plain text pasted onto the canvas becomes an editable text layer. Input fields retain their normal text clipboard behavior. External Figma/SVG clipboard formats and viewport-aware placement remain pending.

Use **Paste to replace** in the PixlPrfct menu or **Ctrl/Cmd Shift R** after copying layers. Each selected top-level destination is replaced with a copy at its top-left position, keeping its parent, stacking position, constraints and auto-layout sizing settings. Copied artwork retains its own dimensions; auto layout may resize or reposition it. Selected descendants of another selected layer are replaced with that ancestor only once. The entire operation is one undo step. Locked destinations and protected instance children cannot be replaced. Portable copies are detached layers, as with ordinary paste.

In vector editing mode, double-click a segment to insert an anchor without changing the curve. Click an anchor to select it, use arrow keys to nudge (Shift for ten pixels), Delete to remove it, or the inspector's Make smooth/Make corner actions to change its handles. Each edit supports undo and persists in saved files/SVG. Closed paths retain at least three anchors and open paths at least two; exit vector editing before deleting a whole layer. Deleting an anchor reconnects the remaining neighbors using their existing handles, so it can change the curve.

Auto layout supports horizontal/vertical flow, gap, four padding values, cross-axis alignment, main-axis alignment/space-between, hug width/height, and child fill width/height. Press Shift+A to infer a row or column from the current positions, spacing and order. Existing frames derive paired padding from their contents; a single object gets a transparent wrapper with 10 px padding. Vertical layouts fill full-width children while keeping narrower children fixed. Alt+Shift+A removes auto layout without moving its contents. Empty layouts retain their size, and editing a dimension switches only that axis to Fixed. Set Flow to None to remove layout. Children reflow after insert/delete, resize, visibility changes, or reordering; drag inside a layout to change order. Ignore auto layout leaves a child positioned independently. Nested layouts resolve in the Rust engine and save/export with their computed geometry. As in [Figma's sizing rules](https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout-in-Figma), a fill child switches parent hugging off on the corresponding axis. Enable **Wrap children** for rows or columns that break at the available main-axis size. Wrapping fixes that axis while the cross axis can hug the lines. Row / column gap can be independent (leave blank to inherit Gap), and Wrapped lines supports start, center, end, space-between, or stretch within a fixed cross size. **Size limits** sets optional minimum/maximum width and height on any layer; fill children share available room while respecting their bounds. Bounds also apply to nested layouts and instance overrides, persist in files/history, and scale with the Scale tool. A minimum can intentionally overflow a smaller parent. Grid controls are described below; on-canvas padding and flex gap handles are available. Groups participate as single layout children.

Appearance controls include layer opacity, uniform or independent corner radii for rectangles/frames/images, fill visibility, and an independent solid stroke color and weight. Frame opacity composites the frame and its descendants together; rounded frame clipping also applies to selection and SVG export. The Scale tool scales radii and enabled stroke weights. Strokes are currently centered; multiple paints, stroke alignment and background blur remain pending; drop/inner shadows and layer blur are available.

Children of frames have independent horizontal and vertical constraints: left/top, right/bottom, center, both edges, or scale. Set these in the Constraints inspector, including for multiple selected children. Resizing a frame by its handles or dimensions updates nested children in one undo step, with a live drag preview. Both-edge stretching clamps at a one-pixel minimum when the frame becomes too small. The K Scale tool explicitly scales the entire subtree and bypasses resize constraints. Text box constraints do not scale font sizes. These modes follow [Figma's constraint behavior](https://help.figma.com/hc/en-us/articles/360039957734-Apply-constraints-to-define-how-layers-resize); layout guides and grid auto layout are described below.

Place PNG, JPEG, or WebP images with the toolbar image button or Ctrl/Cmd+Shift+K. You can also drop files onto the canvas or paste an image from the clipboard. The inspector supports fit, fill/crop, crop zoom and position, reset, and replacement. Images and crops persist in `.pixl` files and are embedded in SVG exports. Imports are resized to at most 2048 pixels on their longest side; encoded image data is limited to 2 MB per image and the complete document to 5 MB. Larger images may need compression before import. SVG import supports editable paths and supported linear/radial paints; consult the detailed import section and roadmap for limitations.

## Architecture

`src/lib.rs` owns versioned documents, shapes, mutations, history, hit testing, and validation. It builds as both a native Rust library and a WASM module. The Electron desktop app bundles the same WASM engine and web editor.

`web/app.js` adapts pointer and keyboard input to the Rust engine and draws the returned document using Canvas 2D. HTML/CSS supply the editor interface. Rendering and browser UI are currently JavaScript; this is not an all-Rust UI or GPU renderer.

`tests/wasm.test.mjs` exercises the compiled browser WASM bindings in Node; Rust unit tests cover history, loading, and hit testing. This does not replace visual or pointer-interaction testing in a real browser.

## Current limits

Managed cloud documents are private to the signed-in account. Self-hosted installations support organization/team workspaces and protected libraries; real-time multiplayer collaboration, nested instance-swap overrides and Boolean operations remain unimplemented. Polygon and star use fixed point counts. Paths support separate solid fill and stroke colors, round stroke caps/joins, and a 4096-point limit. Their selection bounds include control handles. Frames support nested parent relationships, movement with descendants, subtree duplication/deletion, inherited visibility, and expandable layer trees. Assign layers with Parent frame → Move into frame; choose Page to detach. Coordinates are currently page-relative. Frames have a Clip content toggle, respected by rendering, selection, and SVG export. New UI-created frames clip by default; old documents retain their previous overflow behavior. Drawing starts inside the frontmost visible frame at the initial pointer position. Dragging uses the moved selection’s center to choose a destination frame, with reparenting and movement in one undo step; direct drags of individual group members retain their parent. Multi-selection supports proportional scaling, but not independent width/height stretching. Marquee intersects bounding boxes; no deep selection of nested objects is available. Alignment targets the selection bounds, not a parent frame. Text supports one style per box and clips to the box, with a warning in the inspector. Fonts are limited to Manrope, DM Sans, Georgia, and the system monospace font. Manrope and DM Sans load from Google Fonts; system fallbacks apply when unavailable. SVG uses the same measured wrapping and alignment as the canvas, but still depends on fonts available in the viewing application (fonts are not embedded).

Interface references: [current navigation](https://help.figma.com/hc/en-us/articles/360039831974-Explore-the-navigation-bar-and-left-sidebar), [selection](https://help.figma.com/hc/en-us/articles/360040449873-Select-layers-and-objects), and [alignment and distribution](https://help.figma.com/hc/en-us/articles/360039956914-Adjust-alignment-rotation-position-and-dimensions). Unimplemented Figma features are not presented as functioning controls.

Local storage belongs to this browser and origin; use **Save file** for portable backups. Multiple tabs do not merge edits. The Electron desktop app packages the same editor for macOS and Windows; see [Desktop builds](docs/DESKTOP.md).

Use **+ New page** in the Pages sidebar to start another canvas. Select a page and use **Rename** or **Delete page** below the list. At least one page must remain. On narrow screens the page picker and page controls appear above the canvas. Save files include every page; artwork export includes the current page or selected layers. Version 1 files and existing local designs automatically migrate to Page 1 in the version 2 format. Page navigation does not consume undo history; undo/redo of an edit returns to its saved active page.

## Hosting

The full `dist/` output is a Sites Worker application with static editor assets and D1 `DB` and private R2 `BUCKET` bindings. Sites supplies authenticated user identity and applies the committed Drizzle migrations before deployment. Preserve `.openai/hosting.json` and the existing private audience. Build with `npm run build`; generated `dist/`, `public/editor/`, and `web/pkg/` are not committed. No custom OAuth provider or application secrets are required.

For an ordinary static web host, `npm run build:static` writes `.static/`: the local-only editor as plain files, with the project list at `/` and the editor at `/editor/`. Serve it from its own domain or subdomain, because the pages use root-relative paths. Projects stay in each visitor's browser, and account, cloud-file and team-library features are left out (see `web/static-host.js`). The generated `.htaccess` serves `.wasm` with the right type and turns off long-lived caching, since no file carries a version in its URL.

Export opens a dialog for PNG or SVG, current page or selection, 0.25–8× scale, and transparent or solid backgrounds. Selection export includes selected frame descendants and their clipping/opacity, independently of unselected ancestors. PNG waits for embedded images and fonts, then uses the same compositing renderer as the canvas. PNG output is limited to 8192 pixels per edge and 16 megapixels; deeply nested translucent frames have an additional memory limit. SVG retains editable vectors and embedded images, but relies on available fonts. PDF and slice export remain pending; JPEG and batch ZIP export are available.

Text sizing supports Fixed size, Auto width (hard line breaks), and Auto height (wrap to the current width). Auto width text with a maximum width wraps at that limit and grows vertically. New text uses Auto width; pasted plain text uses Auto height. Editing width switches Auto width to Auto height; editing height switches to Fixed size. Fill width inside auto layout switches Auto width to Auto height, and Fill height uses Fixed size. Browser font measurements feed the Rust layout transaction, so text edits, wrapping after parent resize, nested hug sizes, and undo stay together. Native consumers without a text measurement provider retain stored text dimensions. Existing files default to Fixed size.

Fill controls support solid, linear gradient, and radial gradient paints on shapes, frames, vectors, and text. Gradients have 2–16 stops, editable hex/color values, stop position and opacity, add/remove, and color reversal. Start/end coordinates are percentages of the layer bounds; radial start is the center and the distance to end controls radius in normalized bounds. Radial fills scale with the layer aspect ratio. They survive undo, copy/paste, scaling, save/load, PNG, and SVG. Canvas radial fills use cached tiles sized for the current drawing transform, bounded to 8192 pixels per edge and 16 megapixels; SVG retains vector gradients. Angular/diamond gradients, independent radial-axis editing and multiple fills remain pending; gradient strokes are available.

Choose Edit gradient on canvas in Fill to drag square endpoints and circular color stops. Double-click the gradient line to insert an interpolated stop. Shift snaps endpoint directions to 45° and stop positions to 10% increments. Tab cycles handles while the canvas has focus; arrow keys nudge endpoints by 1 px or stops by 1%, with Shift for 10. Delete removes the selected stop while retaining at least two. Enter finishes editing; Escape cancels an active drag or exits edit mode. Each completed drag is one undo step.

Use the padlock beside a layer, Lock selection in the inspector, or Ctrl/Cmd+Shift+L to toggle locks. Locked frames lock descendants through inheritance; unlock the parent to restore canvas access. Canvas hit testing, marquee, select-all, dragging, resizing, scaling, nudging, and vector/gradient editing respect locks. Locked frames are excluded from automatic drawing/drop containment. Layers remain selectable and editable through the layer list and inspector, following [Figma’s documented locking behavior](https://help.figma.com/hc/en-us/articles/360041596573-Lock-and-unlock-layers). Explicit inspector edits, duplication, and clipboard actions remain available. Locked children move with an explicitly transformed unlocked parent. Locks persist in documents and history and do not hide content from exports. Flat groups currently lock through their selected member layers; true nested group containers remain pending.

Select a frame and choose **Create component** to make it reusable. **Insert instance**, or a component in the sidebar library, places a linked copy on the current page. Main-component edits propagate across pages, including added/removed layers, constraints, and auto layout. Instance edits preserve property overrides; **Reset all overrides** restores the main values while retaining placement, and **Detach instance** makes ordinary editable layers. **Go to main component** navigates to its page. Duplicate preserves links; portable clipboard copies deliberately detach links to avoid binding to unrelated IDs in another file. Removing a main component detaches its instances while retaining their last appearance; undo restores the links. Components currently require a frame; exposed instance-swap properties and library sharing remain pending. Detach before adding/removing/reordering instance children.

**Swap component** replaces the selected instance with another main component from any page. Overrides transfer between layers with matching original main-layer names, kinds, and hierarchy; repeated sibling names match by paint-order occurrence. Locally renamed layers still match by their source names. Matched layers retain their instance IDs; unmatched layers take the replacement defaults. Placement and explicitly overridden dimensions remain. Swaps are one undo step and persist in saved files. This supports the core workflow described in [Figma’s instance swapping documentation](https://help.figma.com/hc/en-us/articles/360039150413-Swap-components-and-instances), without claiming identical matching heuristics.

New overrides track individual typography, appearance, constraint, layout-item, and auto-layout properties. For example, overriding alignment still allows main-component font-size edits to propagate. Gradient geometry/stops and image data remain whole-field overrides. Enabling/disabling auto layout overrides the whole layout object. Older whole-object overrides remain supported. Open **Selected layer overrides** in the inspector to reset one property without discarding other overrides, or use **Reset all overrides** for the entire instance. Root placement is retained and omitted from the override list.

Choose **Create variant set** on a main component to define named properties such as State and Size. The set editor lets you add properties, assign existing main components, and edit each variant’s values in a table; each combination must be unique. Changes save as one undo step. **Add variant** duplicates a main component and its subtree into the same set with a unique value; use **Edit variant set** to name that value. The Components library groups each set as one asset and inserts its first variant by default.

Instances expose one selector per variant property. Selection first preserves all other values when the exact combination exists; sparse sets choose the matching value that retains the most other properties, with set order breaking ties. Matching text/style overrides carry over through the existing swap mechanism. Set metadata, additions, deletions, and switches survive history and saved files. Deleting a main removes its set membership; an empty set disappears. Ungroup variant set retains the components and instances. Sets currently organize document metadata and the library, without a canvas container around their main components. Nested components and exposed instance-swap properties remain pending.

**Add component property** on a main component exposes Text or Visibility controls for selected layers. One property can bind several compatible layers; the first selected layer supplies their initial value. Text binds only to text layers, while visibility can bind any layer in that main component. Each field can belong to one property, and names must be unique within a main component. Edit binding changes the name, type, or target layers; Remove releases the binding without deleting layers.

Main components and instances show these controls directly. Changes to a bound layer through the ordinary inspector also update its other bindings. Instance values become ordinary text/visibility overrides, preserving unrelated styling. Property reset restores all of its bindings together; the per-layer override reset does the same for bound fields. Same-named, same-type exposed properties preserve overridden values across component/variant swaps even when target layer names differ. Duplicating a main or adding a variant copies definitions with remapped layer IDs. Deleting targets prunes bindings; undo restores them. Definitions persist in `.pixl` files; portable layer clipboard copies remain detached. Definitions are currently per main component, with no automatic definition propagation to pre-existing variants; use matching names/types across those variants. Nested instance-swap properties remain pending.

Enable **Independent corners** in Appearance to edit top-left, top-right, bottom-right, and bottom-left radii. Disabling it uses the top-left value uniformly. Stored values are preserved when a layer is resized; rendering proportionally reduces them when adjacent corners would overlap. The same geometry drives canvas/PNG, SVG paths, image and frame clipping, hit testing, and drop targeting. Scaling adjusts all four values. Component instances may override the four radii together while inheriting other appearance properties. Corner smoothing remains pending.

Stroke controls include a comma- or space-separated dash pattern (blank for solid), dash offset, butt/round/square caps, and miter/round/bevel joins. Up to 16 nonnegative dash lengths are accepted; an all-zero pattern is rejected. Odd patterns repeat as in Canvas/SVG. Scaling changes dash lengths and offset with the layer. These properties persist through history and component overrides and export in PNG/SVG. Miter joins have an adjustable limit, defaulting to 10 for existing artwork; vector export bounds reserve conservative room for miters and square caps. Selection still follows the underlying path through dash gaps. Stroke alignment and separate start/end decorations remain pending.

Frames support up to eight **Layout guides**: square grids, columns, and rows. Columns/rows have count, gutter, margin, stretch or fixed-size start/center/end alignment, color, opacity, and individual visibility. Stretch guides respond to frame dimensions; fixed guides retain their chosen size. Shift+G or the inspector toggle shows/hides all guides for the current session. Guides are clipped to their frame and clipping ancestors, remain non-interactive, and never appear in PNG/SVG exports. Square grids below four screen pixels per cell or above 4,096 lines are omitted to avoid unreadable dense overlays. Guides persist in files, clipboard, duplication, component overrides, and history; scaling changes their sizes and spacing. Dragging selections and resizing snaps edges/centers to visible guide lines within six screen pixels. Pink hints show matched guides. Hold Alt to bypass snapping or Shift to constrain movement to one axis; hiding guides disables snapping. Auto-layout flow and hug sizing still take precedence when committed. Save a frame’s guides as a named document style, then choose that style on other frames. Linked edits update every linked frame across pages, including component instances unless overridden. Rename, detach, and delete controls are undoable; detach/delete retain resolved guide settings. Direct per-frame guide edits and scaling detach the link, while ordinary duplication retains it. Layer clipboard copies carry resolved guides without cross-document style references. Style names are unique within the file; up to 1,000 styles are supported. Shared external style libraries remain pending.

In **Prototype**, set a layer’s Action to **Navigate to frame** or **Go back**, then choose its Trigger: **On click**, **Mouse enter**, or **Mouse leave**. Destinations may be frames on any page. Use the play button beside Export or **Present prototype** to open the selected layer’s nearest frame (otherwise the first visible frame on the page). The player fits the screen, clips overflow, supports a frame chooser, Back, Restart, and optional hotspot outlines. Expand Screen interactions to activate links with the keyboard or touch, including hover actions. Escape or Close presentation returns to editing. Playback uses a separate navigation history and does not change the design or editing undo stack. Editing locks do not disable interactions.

Prototype links persist through save/load and component overrides. Duplicating connected frames remaps internal destinations; portable clipboard copies preserve links within the copied set and omit external destinations. Removing a destination clears its links, including synchronized instance frames, and undo restores them. Each layer supports one interaction per trigger: click, mouse enter, mouse leave, mouse down, mouse up, and (for frames) after delay. Use Add interaction and the numbered remove controls to manage independent actions, targets and transitions. Triggers already used by another interaction are disabled. Removing the first interaction preserves the others; undo restores the entire list. Older files retain their original interaction and default to click. Mouse enter/leave fire once when the pointer crosses the linked region, respect clipping and the active overlay, and do not repeatedly fire while the pointer stays still. These are explicit actions, not an automatically reversible while-hovering state. Nested hit testing chooses the nearest linked ancestor for each trigger; leaving takes priority over entering another region. Pointer actions are paused during transitions. Choose Instant, Dissolve or a directional Slide, with duration (0–10000 ms) and easing. Reduced-motion preferences skip animation; toolbar navigation and resizing cancel running transitions cleanly. Smart Animate, while-hovering states, multiple actions per trigger, drag triggers, scrolling, variables and conditional logic remain pending.

Prototype actions also support **Open overlay** and **Close overlay**. Pick a destination frame, center, corner or manual X/Y placement relative to the base screen, and optionally Close when clicking outside. Overlays retain their document dimensions at the screen’s display scale, are clipped by the base viewport, and dim the screen underneath. Only the top overlay receives interactions, including keyboard-accessible links. Back dismisses one overlay before going back through screen history; navigation and Restart clear overlays. Up to 16 overlays may be stacked. Links, positions and dismissal settings persist through files, component overrides, duplication, clipboard remapping and undo. Open/close actions support Instant or Dissolve; outside-click dismissal is instant. Set Backdrop color and Backdrop opacity (0–100%) for each overlay action. Manual X/Y coordinates use design pixels from the base screen’s top-left corner, including negative offsets; the viewport still clips overflow. Use **Swap overlay** to replace the top overlay with another frame while keeping its placement, backdrop and outside-click settings. It does not add a stack or history level; Back or Close dismisses the replacement. Swap requires an open overlay and supports Instant or Dissolve. Directional overlay motion remains pending.

Name a frame’s **Flow starting point** in Prototype to create a named entry point. The presentation picker switches flows and resets Back/Restart history to that start. With no selected frame, Present prefers named flows on the current page, then another named flow. Flow names belong to individual frames; new component instances do not inherit their main’s flow name.

Frames also support **After delay**, following the timed-interaction concept in [Figma’s trigger reference](https://help.figma.com/hc/en-us/articles/360040035834-Prototype-triggers). Set **Delay (ms)** from 1 to 600,000, independently of transition duration; the default is 800. Timers start after the screen and its incoming transition are ready, including visible nested frames and component instances. Only the active screen or top overlay runs timers. Each timed action fires once per visit; navigating, opening/swapping/closing an overlay, choosing a flow, Back, and Restart replace the active visit. Returning to a frame starts its delay again. Repainting, resizing, or showing hotspots briefly pauses elapsed time without restarting fired actions. Leaving playback cancels all timers. Ties use layer ID order; navigation cancels remaining actions from the previous visit. Delay settings persist through files, component overrides, clipboard and history. A timed Back or Close with nothing to dismiss is a one-time no-op. Multiple actions per trigger and reversible hover states remain pending.

Turn on **Prototype connections** beside Present to see same-page navigation/overlay wires and named flow labels. Select an unlocked layer and drag its blue right-side handle onto a visible frame to connect it. Existing open/swap overlay actions retain their action and settings; other actions become navigation. Drop on empty space or cancel to leave the link unchanged. A completed connection is one undo step. Use the destination selector for other pages and self-links; wires and flow labels are editor-only and do not export.

Select **Pencil** (Shift P) to draw freehand. The canvas smoothing control ranges from 0–100%, defaulting to 50%. At 0%, sampled points are retained; higher values remove redundant points using a zoom-adjusted tolerance. Releasing the stroke fits aligned Bézier handles at gentle turns while retaining sharp corners and endpoints. The resulting path uses the existing vector point/handle editor and persists through files, clipboard, undo, PNG and SVG export. Preview follows the raw pointer samples; smoothing is applied once on release. Strokes are limited to 4096 samples.

JPEG export is available for the current page or selection, with 0.25–8× scale and 1–100% quality (default 90%). JPEG always uses the chosen opaque background, default white; transparency remains available for PNG and SVG. JPEG shares PNG’s 8192-pixel edge, 16-megapixel output and compositing-memory limits. The exporter verifies the returned MIME type before downloading a `.jpg` file.

Batch export is available through **Top-level frames (ZIP)** and **Selected layers separately (ZIP)**. Each visible root becomes a separate SVG, PNG or JPEG, including its descendants. Selecting a frame and its child exports the frame only once. Filenames are sanitized and duplicate names get numeric suffixes. Scale, quality and background settings apply to every file. The dialog reports progress; raster files render sequentially. Batches allow up to 100 files and 128 MB of encoded data, in addition to each raster file’s memory limits. Files are packaged into one ZIP only after every export succeeds.

In vector editing, select an interior anchor and choose **Split path at anchor**. The path becomes two adjacent layers with separate bounds and the original Bézier segments; the first keeps its layer ID, and both retain paint, parent, group and constraint settings. On a closed path, **Open path at anchor** creates coincident endpoints at the chosen seam without removing a segment. The whole edit is one undo step. Endpoints of open paths cannot be split, and locked paths must be unlocked first. Auto-layout parents may reposition the resulting layers. Normalized gradients follow each new layer’s bounds.

Select two open vector paths with the same parent and choose **Join paths** in the selection inspector. The nearest endpoints are connected, reversing anchor order and handles when needed to preserve each existing curve. Coincident endpoints merge; a gap receives a straight segment. The first selected path keeps its ID, name, paint and layout settings, and the other path is removed. Normalized gradients follow the joined bounds. Locked paths and protected instance structures reject the edit. Joining is one undo step and supports up to 4096 resulting anchors.

Copy layers, select multiple destination frames, then press **Ctrl/Cmd V** to paste an independent copy into every selected frame. The menu also offers **Paste into selected frames**. Copied roots start 16 design pixels from each frame’s top-left corner, with relative spacing retained; auto-layout frames arrange them using their layout rules. Descendants, groups and internal prototype links are remapped independently for each copy. Every destination is part of one undoable transaction, so locked frames, protected instances, invalid payloads or document limits prevent the entire operation. Portable copies are detached, matching normal paste behavior.

Inspector updates are coalesced until the next animation frame, allowing blur, click and Tab navigation to finish before dynamic controls rebuild. Focus and text selection are restored by control identity; uncommitted typing is retained, while committed values refresh from the document. Verified consecutive edits cover prototype offsets/opacity, guide count/gutter/margin and gradient coordinates.

### Editable SVG import

Use **Place image or SVG** (Ctrl/Cmd Shift K), drop an `.svg` onto the canvas, or paste SVG markup. Supported solid-color rectangles, rounded rectangles, ellipses, circles, lines, polygons, polylines, and paths become editable Bézier layers inside a viewport frame. Groups retain nesting and composited opacity. Relative/absolute path commands, smooth and quadratic curves, elliptical arcs, viewBox scaling/alignment, and affine group transforms are supported. Arc conversion follows the [W3C SVG implementation notes](https://www.w3.org/TR/SVG/implnote.html#ArcImplementationNotes), approximating arcs with cubic segments of at most 90 degrees. Import is validated by the Rust engine and is one undo step. Files are limited to 2 MB, 64 hierarchy levels, and 4,096 anchors per path.

This is an initial SVG subset: filled compound/even-odd paths, radial/repeating gradients and gradient strokes, masks, clipping paths, CSS rules, text, images, external artwork references, rotated/skewed symbol viewports, and non-uniformly transformed strokes remain unsupported. SVG miter strokes retain their source limit, including the SVG default of 4. Unsupported artwork produces an error before insertion instead of a partial import. SVG markup is parsed as inert XML and never inserted into the page DOM.

Miter joins have an editable **Miter limit** from 1 to 1,000 in the Stroke inspector. It controls when a sharp join is cut off to a bevel, is dimensionless when scaling, and persists through files, clipboard, component overrides, and undo. Existing documents default to 10 to preserve their prior rendering. Canvas, raster exports, SVG output, and conservative export bounds use the same limit.

Fill and Stroke each have an independent opacity percentage. Images have an Image opacity control. These affect the individual paint operation; layer opacity still composites the entire layer and its descendants. Gradient stop opacity multiplies with fill opacity. Paint opacity persists in the Rust document, component overrides, clipboard, history, and scaling, and is preserved by SVG import/export and PNG/JPEG rendering. Legacy documents default both paints to 100%.

SVG linear-gradient fills import as editable gradients with up to 16 color/opacity stops. Object-bounding-box and user-space coordinates, percentage offsets, gradient transforms, local gradient templates, currentColor from definition ancestry, and default/pad spreading are supported. Curve extrema determine the object bounds. Nonuniform transforms preserve the gradient color parameter by transforming its normal, following [SVG paint-server geometry](https://www.w3.org/TR/SVG2/pservers.html#LinearGradients). One-stop and zero-length gradients retain their solid appearance; cyclic/external references and unsupported gradient features fail before insertion. Existing document limits on normalized gradient coordinates still apply.

Local SVG `<use href="#id">` and legacy `xlink:href` can reference shapes, groups, other uses, and symbols. Each occurrence becomes an independent editable frame tree; inherited paints and transforms are resolved without linking copies as components. Symbols support viewBox meet/slice/none alignment, explicit or percentage dimensions, local gradient coordinates, and axis-aligned viewport clipping. Referenced symbols default to the current viewport size when dimensions are omitted. Cyclic/missing/external references and excessive expansion fail before insertion. Rotated/skewed symbol viewports, symbol reference points, and references to nested SVG roots remain pending.

Multiple interactions persist through duplication, all layer paste modes, save/load and undo. Each destination is independently remapped or removed when its target disappears; unrelated triggers remain intact. Component instances override and reset the interaction collection together. Presentation resolves click and hover actions by trigger, includes every interaction in the keyboard-accessible list, and runs the frame’s timed action even when it is not first. Canvas wires show all destinations; dragging a layer’s connection handle edits its first interaction. This follows the one-per-trigger model in [Figma’s interaction reference](https://help.figma.com/hc/en-us/articles/360040315773-Connect-your-prototype); sequential multi-action chains and conditionals remain pending.

Use **Mouse down / Touch press** and **Mouse up / Touch release** for press-open/release-select menus. The primary mouse button, touch contact, or pen can begin a gesture on the presentation canvas; release resolves against the current active screen or overlay, so it can choose an item revealed by the press. A handled down/up action consumes the browser’s following compatibility click; the next ordinary click works normally. Secondary buttons, unrelated contacts, canceled gestures, and releases outside the canvas cannot activate a release action. As with other pointer actions, active transitions temporarily block activation; use Instant for immediate menu selection. Touch and pen dispatch are covered by unit tests; mouse press/open/release/navigation and subsequent normal clicks are verified in the browser. Hold-to-preview reversible states and drag-scrubbed transitions remain pending.
Drop shadows are available in **Effects** for frames, shapes, images, and text. Add up to eight, edit X/Y offset, blur, positive or negative spread, color, opacity and visibility, and reorder or remove individual shadows. The first shadow is nearest to the artwork; all shadows derive independently from the composed layer silhouette, including clipped children. Positive spread dilates that alpha mask and negative spread erodes it. Layer opacity applies once to the combined artwork and shadows. Parent frame clipping still clips child effects, while a frame’s own shadow extends outside its own clip. Effects scale with the artwork, persist in files and clipboard, and override/reset independently of other component appearance properties.

Canvas, PNG/JPEG and SVG exports include shadows; export bounds reserve offsets, spread and three Gaussian standard deviations. Blur uses half the entered blur value as its standard deviation. PNG pixel checks cover hard offsets, rounded silhouettes, blur/spread extents and group opacity. Preview compositing buffers are limited to 8,192 pixels per edge and 16 megapixels, with reduced sampling for extreme sizes/zoom. Raster export rejects effects that would need reduced sampling or exceed the aggregate buffer budget, rather than silently lowering output quality. Layer/background blur remains pending.

Each effect’s **Type** can be **Drop shadow** or **Inner shadow**, sharing the eight-effect stack. Inner shadows use the inverse composed alpha mask, positive/negative spread, blur, offsets, color and opacity, then shade atop the source without changing its alpha. They remain inside the original silhouette and do not expand export bounds. Drop shadows sit behind the artwork; inner shadows sit over it, with list order controlling each kind’s stacking. Files created before effect types default to drop shadows. Component inheritance, independent shadow overrides, scaling, history and SVG/PNG/JPEG output support both types. PNG checks verify hard inside edges, blurred translucent fills, rounded transparency and unchanged dimensions.
# Layer blur

The Effects inspector includes Layer blur. It blurs the composed layer, its children and shadows together; parent frame clipping still applies. Blur follows scaling, supports independent component overrides and undo, and survives document and clipboard round trips. Canvas and PNG/JPEG output use bounded offscreen buffers; SVG retains a Gaussian filter. Export bounds include the blur margin while selection and layout keep their original geometry. Raster exports reject effects that exceed the full-resolution buffer budget.

Radial SVG fills import as editable gradients, including rotated/skewed ellipses, object-bounding-box and user-space units, inherited definitions, and off-center focal circles. The fill inspector exposes focal position and radius. Endpoint edits preserve the transformed ellipse; canvas and SVG/PNG/JPEG exports retain the same geometry. Focal circles outside the outer circle are clamped to its boundary. Repeating gradients and focal radii larger than the outer radius remain unsupported and produce explicit import errors. Geometry follows the SVG 2 paint-server model: https://www.w3.org/TR/SVG/latest/pservers.html

Strokes support independent solid, linear and radial paints. The Stroke inspector provides gradient geometry, focal-circle and color-stop controls plus canvas editing with drag, keyboard nudging, stop insertion/removal and undo. Fill and stroke definitions remain separate through components, clipboard and SVG import/export. Radial paint buffers cover the stroke outside the path bounds, including cap and join reach. PNG verification samples the outer stroke and the untouched fill independently. Existing restrictions on nonuniformly transformed SVG strokes still apply.

### Cloud version history

Open a cloud file, then choose **Cloud files → Version history**. Save named checkpoints, restore a checkpoint, or open it as a separate cloud file. Restoring is revision-checked and atomically saves the replaced design as **Before restore**. Snapshots are immutable and private to the file owner. History loads 40 versions at a time and supports older pages. Automatic backups preserve the prior saved document on the first subsequent edit and at most once every five minutes during continued saving. Backup creation and the new save are one transaction, so failed or stale writes create no history entry. These join explicit checkpoints and pre-restore backups; they are not a snapshot of every keystroke. Apply the new local migration `drizzle/0001_round_ink.sql` once using the same local D1 command as the initial migration. Previously applied migrations remain unchanged.

Automatic history adds `drizzle/0002_lying_hemingway.sql`; apply this new migration once to local preview using the documented D1 command. Hosted migration application remains part of Sites deployment.

Cloud document bodies up to 1.5 MB remain inline in D1; larger bodies use immutable SHA-256-addressed objects in private R2 so the editor’s 5 MB document limit does not exceed D1’s 2 MB row limit. Ownership is checked before retrieving object-backed content, and history snapshots preserve references to immutable bodies. A failed object upload leaves the previous document and history unchanged. Old inline documents remain readable. Unreferenced uploads from interrupted database writes are retained conservatively; quota management and garbage collection remain future work.

Open vector paths now have independent **Start tip** and **End tip** controls in Stroke: line arrow, triangle, reverse triangle, diamond and circle. Tool default preserves existing arrow artwork. Tips follow curve tangents, inherit stroke paint/opacity, and participate in hit testing, exports and component overrides. Split paths retain only their original outer tips; joined paths retain the tips at the surviving ends.

Select an auto-layout frame and choose **Edit spacing on canvas**. Orange handles adjust padding, item gaps and wrapped row/column gaps with live Rust layout preview. Tab cycles spacing controls; arrows adjust the active control, Shift uses 10 px increments, and Alt matches opposite padding. Escape cancels a drag or exits spacing mode; Enter commits and exits. Each completed drag is one undo step. Space-between gaps remain automatically distributed and use the inspector to change distribution.

The Stroke **Position** control supports Inside, Center and Outside for rectangles, frames, ellipses, closed vector paths, text and image outlines. Open paths retain centered strokes. Alignment preserves editing dimensions, scales with stroke weight, supports instance overrides and exports through geometry masks so PNG and SVG keep the same placement and opacity. Older documents keep centered strokes. Auto-layout frames can include inside strokes in their measurements.

### Stroke-aware auto layout

The Auto layout inspector includes **Include inside stroke in layout**. When enabled, an inside frame stroke reserves space before padding on all four edges. Hug dimensions, wrapping, fill sizing, child placement and canvas spacing handles use the same inner bounds. Center/outside strokes do not affect layout. Each nested frame controls its own inclusion; component instances can override/reset the setting. Newly created auto layouts enable inclusion; older files without the field retain their previous excluded setting. Padding and included borders impose a minimum size even when a smaller maximum is configured. Fill frames share available content space while accounting for their individual padding and included borders.

Auto layout supports **Space around** and **Space evenly** in the main-axis and wrapped-line alignment controls. These replace the stored numeric gap and distribute remaining space after padding, borders and child sizes. A single item is centered; overflowing stacks receive no extra space. Fill children consume available space before distribution. Automatically distributed gap handles are hidden while padding remains editable.

Explicit auto-layout gaps and wrapped row/column gaps accept negative values for intentional overlap. Hug dimensions cover the complete child extent, including gaps large enough to reverse item positions. Canvas gap handles show and edit overlap regions; padding remains nonnegative. Wrapping and gap handles share the same row-packing rules, keeping overlapping rows distinct. Between/Around/Evenly use automatic nonnegative spacing instead of the stored numeric value; switching back to Start/Center/End restores that value.

Horizontal auto layouts offer **Align text baselines**. The first line of each text child shares an alphabetic baseline, measured from the same canvas top origin used for rendering. Non-text children align their bottom edge to that baseline. Each wrapped row aligns independently, and hug sizing accounts for both ascent and descent. Hidden and absolute children do not participate. The setting persists and supports component overrides/reset; vertical flow retains it without applying it. Font loading refreshes measurements. Baseline metrics are derived rather than stored in design files; headless/native callers without a font measurer use an approximate font-size fallback.

Auto layout **Canvas stacking** switches between **First child on top** and **Last child on top**. This changes paint order, not layer-panel order or layout positions. Nested child subtrees stay together. Canvas/raster rendering, SVG export, editor and prototype hits, and frame drop targeting honor the setting. Legacy layouts default to last-on-top; component instances can override/reset stacking independently.

### Grid auto layout

Choose **Grid** in a frame’s Auto layout → Flow control. Set columns and explicit rows (zero rows means automatic), then expand a track to choose fixed pixels, hug contents, or weighted fractional sizing and optional minimum/maximum limits. Automatic rows share their sizing settings. Column and row gaps and four-sided padding are independent. Visible children fill cells in row order; hidden and absolute children do not occupy cells.

Select a child to set its one-based column/row, row/column spans, and horizontal/vertical cell alignment. Empty positions use automatic placement. Spans enable fill on their axis; fill can then be changed independently. Dragging a layer reserves the cell under its center and reflows other children; the complete move is undoable. Collisions advance to a free cell instead of discarding content. Fractional tracks share remaining space after fixed/hug tracks while respecting bounds; fixed content may overflow a smaller cell. Nested layouts, component overrides, local/cloud files, scaling, and exports retain the grid.

Choose **Edit spacing on canvas** for grid padding, row/column gutters, and track edges above/left of the frame. Drag an edge or use Tab and arrow keys to resize its track; Shift adjusts by ten pixels. Resizing converts that track to fixed sizing, respecting its limits, while other fractional tracks reflow. Resizing an automatic row creates explicit rows through that row. Previews use the Rust layout engine and commit in one undo step; Escape cancels an active drag. Up to 128 tracks per axis expose canvas handles. Expand a track and choose **Move earlier/later**, or select its canvas edge and use Alt + arrow, to reorder it. Connected spans move as a block, including spans crossing the destination; sizing and cell placement travel together while paint order stays unchanged. Automatic rows become explicit when reordered, and visible cells become pinned to preserve their arrangement. Hidden pinned cells follow their tracks. Reordering supports up to 128 tracks per axis and is undoable. Direct drag reordering, multi-track selection, and direct track deletion remain pending. Groups participate as single layout children.

The right inspector uses compact paint rows (swatch, editable hex, opacity, visibility and removal), paired appearance fields, section add actions, a component shortcut, and collapsible effect/guide settings. Effects can be added, hidden, edited and removed through compact rows. This improves the reference-panel structure; it does not implement missing rotation, masks, blend modes, multi-paint stacks or Boolean operations.
