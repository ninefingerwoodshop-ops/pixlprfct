# Simulated team acceptance — 2026-10-30

User authorization: implement the team workflow and simulate teammates because no
test participants are available. All names and accounts below are synthetic.

| Actor | Scenario |
| --- | --- |
| Simulated Owner | Create a workspace/file, assign access, edit, hand off |
| Simulated Designer | Request editing, load latest, edit, disconnect/recover |
| Simulated Reviewer | Comment/reply/resolve without artwork permission |
| Simulated Viewer | Read file and threads; cannot edit or post |
| Simulated Outsider | Cannot read the workspace file or its threads |

Verified with real BetterAuth sessions, SQLite and the production HTTP server:

- Exclusive editing, token privacy, handoff, revision conflicts, lease expiry,
  membership removal and file-access revocation.
- A slow large upload authorized before handoff/removal cannot commit afterward.
- Attributed comments and idempotent retries, resolution revision checks, and
  artwork revision unchanged by review activity.
- Four separate Chromium contexts complete editing/review/handoff. A network
  interruption preserves local work and reconnect saves it. A server restart and
  a restored SQLite backup retain the saved design and resolved comment.
- Author-approved library properties, sizing and variant selection work while
  source/style/structure/detach protections remain enforced.
- Existing editor workflows and screenshot baselines remain passing.

Evidence is generated by `tests/team-collaboration.test.mjs`,
`tests/team-session.test.mjs`, `tests/library-overrides.test.mjs` and
`tests/browser/team.spec.mjs`. Local run logs and screenshots are retained under
`.local/team-pilot-2026-10-30/`. Figma Share and Comments references were inspected
live before implementation. Share dialog width/header and custom role dropdowns
are checked; this does not certify every state as pixel-identical.

Human participants: **0**. These results establish tested behavior, not whether
teams find the product understandable or valuable. The remaining participant
protocol stays in [PILOT_PLAN.md](PILOT_PLAN.md). Real OS sleep, provider-specific
restore drills beyond SQLite, real email delivery, notification workflows and
simultaneous co-editing are not covered by this simulation.
